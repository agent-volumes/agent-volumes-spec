Agent Volumes defines a universal packaging and distribution standard for the AI agent component ecosystem. Like npm for JavaScript or PyPI for Python, Agent Volumes gives you a single, interoperable way to package skills, tools, hooks, MCP servers, LSP servers, commands, and autonomous agents — and distribute them to any compatible runtime.

## Why Agent Volumes?

AI agent runtimes — Claude Code, Codex, Gemini CLI, Cursor, and others — all define their own incompatible component layouts. Agent Volumes solves three structural problems that block ecosystem growth:

<CardGroup cols={3}>
  <Card title="Fragmentation" icon="puzzle-piece">
    Write a skill or tool once and distribute it to any compatible runtime — no more duplicating work for each
    ecosystem.
  </Card>
  <Card title="No supply chain identity" icon="fingerprint">
    Every volume gets a globally unique `pkg:volume/...` identifier with cryptographic provenance and content integrity.
  </Card>
  <Card title="No shared trust model" icon="shield-check">
    Publisher verification, content hashing, SLSA provenance, and security advisories are first-class features.
  </Card>
</CardGroup>

## Get started

<Steps>
  <Step title="Create a volume manifest">
    Add a `volume.toml` file to your project root and declare your components.
  </Step>
  <Step title="Declare your components">
    List skills, tools, hooks, MCP servers, and other component types you want to export.
  </Step>
  <Step title="Publish to a bibliotheca">
    Use the `shelf` CLI or the Registry API to publish your volume to a compatible registry.
  </Step>
  <Step title="Install in any compatible runtime">
    Any runtime that supports Agent Volumes can discover and install your components.
  </Step>
</Steps>
